# Steps 10–15 implementation changes

## Amendment and requote

- An Open RFQ can hold one Draft Revision while its confirmed Revision and current quote remain operational.
- Sales inline edits autosave Notional, Settlement Date, and Sales/Trading Message into the Draft and highlight changed cells.
- Confirm supersedes the prior Revision, confirms the Draft, changes the request to `Requested/Revised`, clears the current quote association, and creates/seeds the new WorkingQuote.
- Discard leaves the live Revision, quote, and RFQ state unchanged.
- Bulk Confirm/Discard return per-Case outcomes.
- Create New from Existing creates a new Case, reruns routing/defaults, copies only canonical condition fields, and records Case/Revision provenance.

## Remaining lifecycle

- Added Withdraw (`Quoted` and not Presented), Cancel, Reopen, and idempotent Expiry transitions.
- Cancel retains working/history data and Draft amendment but releases ownership.
- Reopen and Expiry return to `Requested` without resurrecting a ConfirmedQuote.
- A configurable hosted worker scans expired quotes; Development uses a two-second interval.

## Events and refresh behavior

- Added parent `events` and child `rfq_events` / `quote_events` JSONB tables.
- Event IDs are allocated under a locked single-row cursor inside the state transaction, so the cursor is commit-order safe.
- Added filtered persisted-event query and an SSE `changed` wake-up endpoint.
- The UI shows Updates Available and keeps explicit refresh semantics instead of silently replacing editable grid data.

## Operational surfaces

- Added capped server-side Past RFQ search, Revision history, ConfirmedQuote history, EOD owner summary, independent mock-backed scratch Pricer, and persisted versioned User Grid Config APIs.
- Queries are desk/user scoped where applicable; searches above 20,000 rows request narrower filters.

## Concurrency and errors

- Existing CaseCurrent, mutable Revision, and WorkingQuote optimistic versions remain authoritative.
- API errors expose stable `Validation`, `Conflict`, `Forbidden`, `NotFound`, and `CalculationFailure` codes.
- Frontend mutation failure reloads authoritative data and discards the stale edit.
- Bulk commands isolate failure per Case.

## Demo readiness

- Development seed now creates 750 deterministic RFQs across Draft, Requested, Quoted, Presented, Cancelled, Hit, and Away; `RFQ_SEED_PROFILE=large` creates 5,000.
- Seed execution remains marker-based and idempotent.
- README documents exact startup commands, local identities, demo journeys, and intentionally deferred production integrations.
